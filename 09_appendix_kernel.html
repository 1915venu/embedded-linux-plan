VIRTUAL MEMORY — How It Actually Works

Address Translation

User Process View:
  Virtual Address 0x00007FFF_12345678

  ┌─────────┬─────────┬─────────┬─────────┬──────────┐
  │  PGD    │  PUD    │  PMD    │  PTE    │  Offset  │
  │ (9 bits)│ (9 bits)│ (9 bits)│ (9 bits)│ (12 bits)│
  └────┬────┴────┬────┴────┬────┴────┬────┴─────┬────┘
       │         │         │         │          │
       ▼         ▼         ▼         ▼          │
  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐  │
  │ Page   │→│ Page   │→│ Page   │→│ Page   │  │
  │ Global │ │ Upper  │ │ Middle │ │ Table  │  │
  │ Dir.   │ │ Dir.   │ │ Dir.   │ │ Entry  │  │
  └────────┘ └────────┘ └────────┘ └───┬────┘  │
                                        │       │
                                        ▼       │
                              Physical Page ────┤
                              Frame Address  + Offset
                                                │
                                                ▼
                              Physical Address 0x0000_1234_5678

TLB (Translation Lookaside Buffer):
  Cache of recent translations. Hit → 1 cycle. Miss → page table walk.
  Context switch → TLB flush (expensive!) unless using ASID.

Page Fault Handling

Types of page faults:
1. MINOR fault: Page exists but not in memory
   → Allocate physical frame, fill from backing store, update PTE
   → Example: first access to mmap'd file page

2. MAJOR fault: Page must be fetched from disk
   → Read from swap or file, very expensive (~10ms)
   → Example: swapped-out page

3. INVALID fault: Accessing unmapped address
   → SIGSEGV → process killed
   → In kernel: oops/panic

4. PROTECTION fault: Writing to read-only page
   → If COW: copy page, make writable (minor fault)
   → If truly read-only: SIGSEGV

Why This Matters for Driver Development

1. copy_to_user() may trigger page fault
   → User page might be swapped out
   → That's OK — kernel handles it transparently
   → But can't call copy_to_user from ISR (can't sleep to handle fault!)

2. mmap() in your driver
   → You set up virtual → physical mapping for device registers
   → User accesses device through normal memory operations

3. DMA considerations
   → Physical addresses for DMA ≠ virtual addresses
   → Pages might not be physically contiguous
   → Use DMA API for proper address translation

PROCESS SCHEDULING

The Completely Fair Scheduler (CFS)

CFS uses a red-black tree ordered by "virtual runtime" (vruntime):

  Tasks sorted by vruntime:

         ┌───────────────────────┐
         │      RB-Tree Root     │
         └───────────┬───────────┘
                     │
              ┌──────┴──────┐
              │             │
         ┌────┴───┐    ┌───┴────┐
         │Task A  │    │Task C  │
         │vrt=100 │    │vrt=300 │
         └────┬───┘    └───┬────┘
              │            │
         ┌────┴───┐   ┌───┴────┐
         │Task B  │   │Task D  │
         │vrt=200 │   │vrt=400 │  ← Highest vruntime
         └────────┘   └────────┘

  Leftmost node (lowest vruntime) runs next.
  When task runs, its vruntime increases.
  Nice value affects rate of vruntime increase:
    Nice -20 (high priority): vruntime increases slowly → runs more
    Nice +19 (low priority): vruntime increases fast → runs less

  Result: all tasks tend toward equal CPU time.

Real-Time Scheduling Classes

Priority levels (lower number = higher priority):

  SCHED_DEADLINE   ─── Earliest Deadline First (highest)
  SCHED_FIFO      ─── First In, First Out (real-time)
  SCHED_RR        ─── Round Robin (real-time)
  SCHED_NORMAL    ─── CFS (default for user processes)
  SCHED_BATCH     ─── CFS, optimized for throughput
  SCHED_IDLE      ─── Only when system is idle (lowest)

For embedded RT:
  - Critical tasks: SCHED_FIFO with high priority
  - Kernel thread priority: set via kthread API
  - PREEMPT_RT: makes most kernel code preemptible

INTERRUPT HANDLING — COMPLETE PICTURE

Interrupt Flow

Hardware Interrupt Occurs (e.g., I2C transfer complete)
        │
        ▼
1. CPU saves context, switches to interrupt stack
2. Interrupt controller identifies IRQ number
3. Kernel calls registered handler (your top half)
        │
        ▼
┌──────────────────────────────────────────────────────┐
│  TOP HALF (Hard IRQ Handler)                          │
│  - Runs with interrupts disabled on this CPU          │
│  - MUST be fast! (< 1μs ideally)                     │
│  - Can: read HW status, ack interrupt, set flags      │
│  - Can: spin_lock (not _irqsave — already in IRQ)    │
│  - CANNOT: sleep, mutex, kmalloc(GFP_KERNEL), I2C    │
│  - Schedule bottom half if needed                     │
│  - Return IRQ_HANDLED or IRQ_WAKE_THREAD              │
└──────────────────────┬───────────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────────┐
│  BOTTOM HALF (choose one):                            │
│                                                       │
│  SOFTIRQ (lowest latency)                             │
│  - Pre-defined, used by networking, block I/O         │
│  - Cannot sleep                                       │
│                                                       │
│  TASKLET (obsolescent)                                │
│  - Built on softirq                                   │
│  - Cannot sleep, serialized per-CPU                   │
│                                                       │
│  WORKQUEUE (most flexible) ← RECOMMENDED              │
│  - Runs in kernel thread                              │
│  - CAN sleep, CAN use mutex, CAN do I2C/SPI          │
│  - schedule_work(&my_work)                            │
│                                                       │
│  THREADED IRQ (modern preferred) ← BEST FOR DRIVERS   │
│  - request_threaded_irq(irq, hard, thread, ...)       │
│  - Hard handler: quick ack → IRQ_WAKE_THREAD          │
│  - Thread handler: full processing, CAN sleep          │
│  - Dedicated kernel thread per IRQ                     │
└──────────────────────────────────────────────────────┘

Threaded IRQ Example

/* Modern interrupt handling — preferred in new drivers */

static irqreturn_t sensor_hard_irq(int irq, void *dev_id)
{
    struct my_device *dev = dev_id;
    uint32_t status;

    /* Quick: read status register */
    status = readl(dev->regs + STATUS_REG);

    if (!(status & INT_PENDING))
        return IRQ_NONE;  /* Not our interrupt */

    /* Acknowledge interrupt in hardware */
    writel(status, dev->regs + STATUS_REG);

    /* Store status for thread handler */
    dev->irq_status = status;

    return IRQ_WAKE_THREAD;  /* Schedule threaded handler */
}

static irqreturn_t sensor_thread_handler(int irq, void *dev_id)
{
    struct my_device *dev = dev_id;

    /* This runs in process context — CAN sleep! */
    mutex_lock(&dev->lock);

    /* Read data via I2C (would block in hard IRQ!) */
    dev->last_reading = i2c_smbus_read_word_data(dev->client, DATA_REG);

    /* Wake userspace */
    dev->data_ready = true;
    wake_up_interruptible(&dev->wait_queue);

    mutex_unlock(&dev->lock);
    return IRQ_HANDLED;
}

/* In probe: */
devm_request_threaded_irq(dev, irq,
    sensor_hard_irq,       /* Top half */
    sensor_thread_handler,  /* Bottom half (threaded) */
    IRQF_ONESHOT,          /* Don't re-enable IRQ until thread finishes */
    "my-sensor", data);

POWER MANAGEMENT

Runtime PM (for drivers)

/* In probe: */
pm_runtime_enable(dev);
pm_runtime_set_active(dev);

/* Before accessing hardware: */
pm_runtime_get_sync(dev);   // Wakes device
/* ... access hardware ... */
pm_runtime_put(dev);        // Marks idle, may power down

/* Callbacks in driver: */
static int my_runtime_suspend(struct device *dev) {
    /* Power down hardware */
    return 0;
}

static int my_runtime_resume(struct device *dev) {
    /* Power up, re-initialize */
    return 0;
}

static const struct dev_pm_ops my_pm_ops = {
    SET_RUNTIME_PM_OPS(my_runtime_suspend, my_runtime_resume, NULL)
};

Dynamic Debug (Enable dev_dbg at runtime)

# Enable all debug messages from your module:
echo 'module temp_sensor +p' > /sys/kernel/debug/dynamic_debug/control

# Enable debug for specific file:
echo 'file temp_sensor.c +p' > /sys/kernel/debug/dynamic_debug/control

# Enable debug for specific function:
echo 'func temp_sensor_probe +p' > /sys/kernel/debug/dynamic_debug/control

# Disable:
echo 'module temp_sensor -p' > /sys/kernel/debug/dynamic_debug/control
